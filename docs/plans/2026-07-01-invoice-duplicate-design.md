# Duplicate Invoice — Design

## Problem

Recurring consulting invoices are currently recreated from scratch every month.
The user wants to clone an existing invoice into a new, fully editable draft —
matching the "Duplicate invoice" pattern found in QuickBooks, Xero, and
FreshBooks — with one extra convenience: line-item descriptions that mention a
month + year (e.g. "June 2026") should roll forward automatically when the
invoice date is shifted a month ahead.

## Decisions (confirmed with user)

1. **Entry point**: a "Duplicate" icon button on every row of the invoice list
   table (`/invoices`), next to Preview/Download. Available regardless of the
   source invoice's status (Draft, Sent, Paid, Cancelled, Written Off).
2. **Date shift**: the new invoice date defaults to the same day of the
   following month, using the existing `advance_recurrence_date` helper
   (already used by recurring profiles), clamped to the last valid day of
   shorter months.
3. **Description rollover**: detect a month name (English/French/Spanish) +
   4-digit year anywhere in each line item's description and advance it by
   the same number of months as the date shift (always 1, for now). All other
   text is left untouched. Computed once when the dialog opens; not
   recalculated live if the user edits the date field afterward.

## Non-goals (YAGNI)

- No `duplicated_from_id` / lineage tracking in the DB — not requested.
- No bulk-duplicate (multiple invoices at once).
- No live re-rollover of descriptions if the date field is edited after the
  dialog opens.

## Architecture

### New pure functions (`app/main.py`, alongside other invoice helpers)

- `shift_month_year_in_text(text: str, months: int = 1) -> str`
  Regex-based detection of a month name (EN/FR/ES) + 4-digit year anywhere in
  `text`. Advances all matches by `months`, preserving the original word's
  capitalization style (Title/lower/UPPER) and leaving everything else in the
  string untouched. Returns `text` unchanged if no match is found.

- `build_duplicate_invoice_prefill(invoice, items) -> dict`
  Returns `{customer_id, date, lines: [{service_id, qty, price, description}]}`
  by combining `advance_recurrence_date` (date) and
  `shift_month_year_in_text` (each line's description).

### Dialog refactor

The "New Invoice" dialog ([app/main.py:593-657](../../app/main.py)) is currently
built once, inline, when `/invoices` renders. It becomes a function:

```python
def create_invoice_dialog(customers, services, prefill=None):
    ...  # builds ui.dialog()/ui.card() fresh, opens it, self-deletes on hide
```

- Called with no `prefill` from the existing "New Invoice" button (unchanged
  behavior).
- Called with `prefill` from the new "Duplicate" row action.
- Dialog title becomes "Duplicate Invoice — from {source.number}" when
  `prefill` is set, "New Invoice" otherwise.
- Every dynamically created dialog registers
  `dialog.on('hide', dialog.delete)` so repeated duplicate clicks don't
  accumulate hidden DOM elements.

### Row action wiring

`invoice_list_columns` / the `body-cell-actions` slot
([app/main.py:697](../../app/main.py)) gains a `content_copy` icon button,
unconditional (unlike `can_send`/`can_mark_paid`/etc.), emitting a `duplicate`
event. A new `duplicate_invoice_action(inv_id)` loads the source invoice +
items from the DB, builds the prefill dict, and calls
`create_invoice_dialog(customers, services, prefill=...)`.

### Data / DB

No schema changes. Saving always creates a brand-new `Invoice` row with an
autogenerated number (`next_invoice_number`) and `status='Draft'`, completely
independent from the source invoice.

## Testing

- Unit tests for `shift_month_year_in_text` (EN/FR/ES months, mixed case,
  year rollover at December→January, no-match passthrough, multiple matches).
- Unit tests for `build_duplicate_invoice_prefill` (date shift + description
  rollover combined, end-of-month clamping).
